# Queris: Evaluated Text-to-SQL Analytics Agent

## Current status

🚧 **Phase 5 is in progress.** Queris can generate deterministic retail and 32-table ambiguous DuckDB fixtures, introspect schemas, request SQL through a replaceable Gemini adapter, validate every statement, execute allowed queries read-only, and score versioned generation and retrieval evaluations. The typed LangGraph state machine retries failed SQL with a configurable cap (default 3) and returns a graceful exhaustion result. Structured retry-count output is the next step. No API or frontend exists yet. See the [`roadmap.md`](roadmap.md#current-focus) for the exact resume point.

## Product vision

A Text-to-SQL agent that answers natural-language questions over analytics data (e.g. *"Which categories lost margin last quarter, and in which regions?"*), running a controlled, auditable flow:

1. Inspects the available schema.
2. Enriches ambiguous identifiers with reviewed business metadata.
3. Semantically retrieves the relevant tables/columns (embeddings + cosine similarity).
4. Generates SQL.
5. Validates that the query is read-only.
6. Executes it on DuckDB.
7. Automatically fixes syntax errors (think-act-observe loop).
8. Shows results, a visualization, and an explanation.
9. Saves the query and the sources used.

The differentiator versus an "API-calling chatbot" is the **evaluation layer**: a set of 50–100 questions with expected SQL, measuring execution accuracy, result accuracy, blocked-unsafe-query rate, average number of retries, latency, and cost — plus adversarial tests (DROP TABLE attempts, prompt injection inside text fields, ambiguous questions, similarly-named columns, unanswerable questions).

## Security boundaries

- **Mandatory read-only mode**: no query generated by the agent may execute `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `CREATE`, or any write DDL/DML. This is enforced with SQLGlot (parsing + statement whitelist) before execution on DuckDB — not via prompting alone.
- **Prompt injection**: any text coming from data (cell values, semantic search results, etc.) is treated as untrusted data, never as an instruction.
- **No system command execution** from the agent's tools; the agent may only call explicitly exposed functions (schema lookup, vector search, validated SQL execution).
- **Traceability**: every executed query and its sources (tables/columns used) must be logged so they can be audited against the evaluation set.

These constraints apply to the first implementation and cannot be deferred to a later phase.

## Retrieval evaluation

The versioned wide-schema evaluation uses a deterministic offline token-hash embedder so tests do
not depend on credentials, network access, or provider model changes. At `k=5`, the 10 reviewed
question-to-column labels produce these macro metrics:

| Schema documents | Precision@5 | Recall@5 |
|---|---:|---:|
| Raw identifiers | 0.14 | 0.70 |
| Reviewed enrichment | 0.20 | 1.00 |

The enriched documents recover all three relevant columns missed by raw identifiers. Reproduce the
comparison after creating the wide fixture:

```bash
queris-retrieval-eval data/wide.duckdb metadata/wide-schema.v1.yaml \
  evals/wide_schema_retrieval.json --top-k 5
```
